# iPhone Monitor

Бот следит за объявлениями iPhone на Авито, считает потенциальную маржу и
присылает карточку сделки в Telegram.

## Как это работает

1. `src/iphone_monitor/avito_api_source.py` дёргает внутренний JSON-фид Авито
   (`https://www.avito.ru/web/1/main/items?locationId=...&categoryId=84`) с
   User-Agent мобильного приложения. HTML-страницы Авито с домашних IP закрыты
   капчей, а этот фид отвечает.
2. Цены всех увиденных объявлений складываются в SQLite
   (`listing_prices`), поэтому «рыночная цена» — медиана цен на такие же
   модель/память/состояние за последние 30 дней, а не по одной странице выдачи.
3. Маржа = рынок − цена − доставка − комиссия − резерв ремонта. Если маржа
   больше `NOTIFY_MIN_MARGIN_RUB`, карточка уходит подписчикам.
4. Если Telegram недоступен, уведомление не теряется: оно попадает в очередь
   `pending_notifications` и досылается, когда связь вернётся.

## Переменные окружения (файл `.env`)

Обязательные:

```env
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
LISTINGS_SOURCE=avito_api
```

Полезные:

| Переменная | Смысл |
| --- | --- |
| `AVITO_API_LOCATION_ID` | 107620 — вся Россия, 637640 — Москва и т.д. |
| `AVITO_API_QUERY` | Слово для поиска, по умолчанию пусто. Авито в этом канале игнорирует формулировку запроса и отдаёт всю категорию телефонов, поэтому реальная фильтрация идёт по названию объявления на стороне бота |
| `POLL_INTERVAL_SECONDS` | Пауза между опросами Авито, не меньше 180–600 (иначе 429). На практике безопасно 900 |
| `MAX_LISTINGS_PER_POLL` | Сколько объявлений просить за один запрос; 100 проверено, больше Авито не отдаёт |
| `NOTIFY_MIN_MARGIN_RUB` | Порог маржи для уведомления, сейчас 500 ₽ |
| `DELIVERY_RUB`, `COMMISSION_RUB` | Расходы на доставку и комиссию |
| `REPAIR_RESERVE_USED_RUB`, `REPAIR_RESERVE_BROKEN_RUB` | Резерв на ремонт б/у и битых |
| `TELEGRAM_TRANSPORT` | `mtproto` или `botapi` |
| `TELEGRAM_PROXY` | `host:port:secret` MTProto-прокси (для mtproto) |
| `DAILY_SUMMARY_TIME`, `SUMMARY_TIMEZONE` | Время ежедневной сводки |

## Ограничения ленты Авито

Проверено на живом фиде:

- Фраза поиска (`query`) и номер страницы (`page`) игнорируются: любой запрос
  отдаёт самые новые телефоны России. Поэтому страницы не листаются, а фильтр
  по iPhone идёт по названию объявления на стороне бота
  (`is_iphone_phone`), аксессуары, чехлы, часы и наушники отбрасываются.
- `limit=100` работает (~90 объявлений в ответе), из них реальных iPhone
  обычно 15–20.
- Rate limit жёсткий: серия из нескольких запросов подряд даёт HTTP 429 и
  блокировку IP на несколько минут. Поэтому интервал 900 секунд, а на 429 бот
  отступает минимум на 5 минут и не падает.

Следствие: примерно раз в 15 минут в историю попадает ~18 живых iPhone.
За сутки это ~1500 цен. Рыночная цена считается по медиане цен на ту же модель,
память и состояние за 30 дней. Двух цен достаточно, только если они расходятся
не больше чем на 15%; одна цена рынком не считается, и тогда уведомления по
этой модели нет — так отсекаются случайные «медианы из одной цены».

## Диагностика

Перед тем как искать ошибку в коде, запустите самопроверку:

```powershell
$env:PYTHONPATH = "D:\tg\src"
D:\tg\.venv\Scripts\python.exe -m iphone_monitor.doctor
```

Она проверяет настройки (интервал, режим Telegram), доступность фида Авито,
связь с Telegram, базу и то, не запущен ли второй экземпляр бота. Каждая
строка `СТОП` — конкретная причина.

## Telegram: почему MTProto

С российских домашних провайдеров `api.telegram.org` блокируется по SNI, а
прямой MTProto тоже не проходит. Рабочая схема: локальный прокси TgWsProxy
(`127.0.0.1:1443`) + `TELEGRAM_TRANSPORT=mtproto`. Пока TgWsProxy запущен,
бот может писать и читать сообщения. Если прокси выключен, уведомления
копятся в очереди и уходят после его включения.

На сервере (Амвера и т.п.) Bot API обычно доступен напрямую, поэтому там
достаточно `TELEGRAM_TRANSPORT=botapi` без прокси.

## Запуск

```powershell
D:\tg\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:PYTHONPATH = "D:\tg\src"
D:\tg\.venv\Scripts\python.exe -m iphone_monitor.main
```

Автозапуск и перезапуск после падения — `tasks/run-bot.ps1`. Скрипт держит
один экземпляр бота (файл-замок `data/bot.lock`), пишет вывод в
`data/launcher-*.log`, а события самого бота — в `data/bot.log`.

## Перенос на сервер (Амвера)

Бот в Docker-образе (`Dockerfile`), без привязки к Windows: в Amvera создайте
проект типа «Docker», загрузите проект, смонтируйте постоянное хранилище в
`/data` и задайте переменные окружения из `.env`. На сервере Telegram Bot API
доступен напрямую, поэтому `TELEGRAM_TRANSPORT=botapi` и `TELEGRAM_PROXY`
оставьте пустыми — прокси нужен только дома.

Один и тот же `.env` не подходит для двух машин одновременно: на сервере
должен работать только один экземпляр бота (файл-замок `/data/bot.lock`
защищает от двойного запуска в пределах одной машины).

### Как перенести историю на сервер

Новая машина начинает с пустой базы: она не помнит, какие объявления уже
видела, и не знает, о каких уже сообщила. Чтобы бот не забыл это при переезде,
в репозитории лежит `assets/seed_state.json` — снимок состояния:

```powershell
# сделать снимок на старой машине (база должна быть не занята ботом)
& .\.venv\Scripts\python.exe tasks\make_seed_state.py
```

Бот при старте один раз вливает этот снимок в базу (история просмотров, уже
отправленные сделки, цены для расчёта рынка) и ставит отметку
`seed_state_applied` в метаданных, поэтому повторно вливать не будет.
Читатели (`chat_id`) в файл не попадают — на сервере их задаёт
переменная `TELEGRAM_CHAT_ID`. Путь к файлу меняется через
`SEED_STATE_PATH`, пустое значение отключает перенос.

### Сколько это стоит и что делать, когда деньги кончатся

Приложение арендуется в Amvera: тариф «Пробный» — 170 ₽ за 30 дней, деньги
списываются с баланса аккаунта понемногу (примерно 4–7 ₽ в сутки). Пока на
балансе есть деньги, контейнер работает сам и перезапускается после сбоев.
Когда баланс кончится, Amvera заморозит приложение: бот перестанет опрашивать
Авито, уведомления и сайт остановятся — но ничего не потеряется, история
останется в /data.

Что делать, когда это случится (по решению владельца):

1. Пополнить баланс в личном кабинете Amvera — контейнер поднимется сам,
   история и настройки останутся на месте.
2. Или на время вернуть бота на домашний компьютер: запустить
   D:\tg\tasks\run-bot.ps1 (нужен включённый компьютер и TgWsProxy,
   потому что дома Bot API заблокирован). Перед этим убедитесь, что облако
   действительно остановлено — иначе объявления будут приходить дважды.
3. После переезда в обратную сторону снова соберите
   tasks\make_seed_state.py и закоммитьте assets/seed_state.json.

Проверить, жив ли облачный бот, можно по снимку сайта: поле status.host
начинается с run-pereekyp- (это Amvera), а status.heartbeat_iso должен
быть свежим (не старше 30 минут при опросе раз в 15 минут).

## Публикация данных на сайте

Бот пишет снимок состояния: статус (живой/нет, пауза, число сбоев
источника, время heartbeat) и последние уведомления. Есть три способа
доставить его на сайт.

1. `GITHUB_TOKEN` + `GITHUB_REPO` — рекомендуемый. Бот коммитит снимок в
   `site/site-data.json` (по умолчанию) через GitHub API, а workflow
   `Deploy website to InfinityFree` публикует его на хостинг. Пароль FTP
   боту не нужен вообще: он живёт в секретах GitHub Actions.
2. `SITE_FTP_HOST` / `SITE_FTP_USER` / `SITE_FTP_PASSWORD` — прямая
   загрузка по FTP (`SITE_FTP_DIR`, по умолчанию `/htdocs`).
3. Ничего не задано — снимок лежит в `data/site-data.json` и никуда не
   уходит.

`SITE_EXPORT_INTERVAL_SECONDS` (по умолчанию 1800) задаёт, как часто бот
обновляет снимок; сразу после нового уведомления снимок публикуется
принудительно, чтобы сайт не отставал от Telegram.

В снимке есть блок `status.diag` — он нужен, чтобы проверять бота на
сервере, не заходя в контейнер: `host` (имя машины, по нему видно, кто
опубликовал снимок — домашний ПК или Amvera), `last_cycle` (время цикла,
сколько объявлений получено, сколько новых, сколько уведомлений, лучшая
маржа), `last_source_error` (последняя ошибка источника и признак
`rate_limited`), а также `seen_total`, `pending_notifications` (очередь
недоставленного в Telegram) и `subscribers`.

Читать снимок с сервера: `gh api repos/<owner>/<repo>/contents/site/site-data.json`.
Если `pending_notifications` растёт, а `notified` стоит на нуле — на сервере
не проходит Telegram, тогда нужен `TELEGRAM_TRANSPORT=mtproto` и прокси.

## Команды бота

`/start` — подписаться на уведомления, `/stop` — отписаться,
`/status` — состояние, `/pause` и `/resume` — пауза мониторинга.
