# VISHIT — сайт и кабинет

Публичный сайт перекупа iPhone и кабинет наблюдения. Сайт не меняет файлы бота и не пишет данные: сервер только читает `data/runtime-status.json` и историю уведомлений из `data/seen.sqlite3`.

## Страницы

| Файл | Что это |
| --- | --- |
| `index.html` | Лендинг: hero-терминал, находки с колонкой «Доставка», три шага, расчёт маржи, тарифы, FAQ, финальный блок |
| `cabinet.html` | Кабинет: фильтры (вся Россия, Авито Доставка, модель, память, маржа, период), 4 KPI, график маржи по дням, таблица находок, статус бота, подписка Pro |
| `admin/logs.html` | Закрытый раздел логов бота: вход по паролю, лента «время — действие — статус — детали», фильтры и пагинация |
| `robots.txt` | Закрывает `/admin/` от индексации (`Disallow: /admin/`) |

Маршрут пользователя: лендинг → кабинет → бот. Все кнопки на главной (шапка, первый экран, тарифы, финальный блок) ведут в `cabinet.html`; подключение мониторинга — только из кабинета, кнопкой «Подключить в боте» на `https://t.me/perekypibot`. На главной прямая ссылка на бота осталась лишь в контактах футера.

Стили обеих страниц встроены прямо в HTML: внешних css/js нет, страница самодостаточна. Логотип — inline-SVG (белая грань + бордо), поэтому он не зависит от растровых файлов.

## Кнопка «Авито Доставка»

Сейчас это визуальная заглушка: фильтр «Все / Есть / Нет» на лендинге и в кабинете, плюс колонка «Доставка» в таблицах. Логики нет — значения статичные. Функционал подключим после запуска сайта, когда в данных бота появится признак доставки у объявления.

## Запуск

Из этой папки:

```powershell
uv run --no-project python server.py
```

Откройте <http://127.0.0.1:8765/> — лендинг, `/cabinet.html` — кабинет.

## Что доступно

- лендинг и кабинет — адаптивные, от телефона до широкого монитора;
- API сервера: `/api/status` (живое состояние бота) и `/api/listings` (история находок);
- страницы пока статические: цифры и находки в кабинете — демонстрационные. Следующий шаг — подтянуть их из `/api/status` и `/api/listings`.

В опубликованной статической версии сайт работает без Python-сервера: страницы открываются сразу, а данные бота показываются как не подключённые.

## Закрытый раздел логов

`admin/logs.html` — только интерфейс: он ничего не знает ни о пароле, ни о
содержимом логов, пока не получит токен от API. В статической публикации на
InfinityFree API нет: ленту отдаёт `src/iphone_monitor/logs_api.py`, который
запускается рядом с ботом (в контейнере Amvera) и читает его `LOG_PATH`.

Откройте `https://<сайт>/admin/logs.html` и, если API живёт на другом домене,
укажите его в адресной строке: `?api=https://<api-хост>`. Токен сессии
хранится только в памяти страницы, в `localStorage`/`sessionStorage` ничего не
пишется. Требования к серверу, переменные окружения и безопасная проверка
описаны в корневом `README.md`, раздел «Логи и закрытый раздел
`/admin/logs.html`».

Важно: скрытая ссылка защитой не является. Прямой запрос к API без сессии
возвращает `401` и не содержит записей; при незаданных `ADMIN_LOGS_PASSWORD` и
`ADMIN_LOGS_SESSION_SECRET` — `503`. `site/admin/.htaccess` добавляет
`X-Robots-Tag: noindex` и `Cache-Control: no-store`, но это лишь гигиена
кэша и индексации.

## Автоматическая публикация

Workflow `.github/workflows/deploy-site.yml` загружает содержимое `site/` в `htdocs/` после изменения сайта в ветке `master`. В GitHub Secrets нужны `INFINITY_FTP_HOST`, `INFINITY_FTP_USERNAME`, `INFINITY_FTP_PASSWORD`. Каталоги `_*` и `tests/` в публикацию не попадают — держите резервные копии вне `site/`. Старый кабинет (светлая тема) больше не входит в сайт: он лежит в `D:\tg\backup\site-2026-10-31\` вместе со своими `app.js`, `styles.css` и тестом.
